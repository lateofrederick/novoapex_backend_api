NOVOAPEX — EVENT-DRIVEN CHECKOUT / CRM DECOUPLING
==================================================
Goal: fix the duplicate-order bug and decouple payment from the CRM
materialiser. Split the fused crm-materialiser order-ledger into a CHECKOUT
pipeline (order + payment) and a slimmed CRM-ENRICHMENT pipeline, coordinated
by a transactional domain-event outbox with a LISTEN/NOTIFY dispatcher.

Decisions locked in:
  * One order at a time per conversation; order creation legal ONLY in CHECKOUT.
  * Reorder requires an explicit state reset (PAID/CANCELLED -> BROWSING).
  * Checkout emits order.created in the SAME tx as the order insert (atomic).
  * order.created fans out via the outbox to payment-init, profile-stats,
    follow-up scheduling.
  * payment.initiated is NOT an event — payment-init enqueues the outbound
    link message directly.
  * Dispatcher = LISTEN/NOTIFY (v2) + poll backstop; consumers are
    at-least-once and idempotent.
  * Turn-level signal (order_confirmed vs preferences) stays a direct fan-out
    from the orchestrator (checkout job + crm-enrichment job), NOT an outbox
    event — the outbox is only for order lifecycle events.
